
Сравнительный анализ LLM
| Критерий  | Облачные модели (OpenAI, YandexGPT) | Локальные модели (Hugging Face: Llama 4, Mistral, DeepSeek) | 
| --------- | ------------------------------------| ------------------------------------------------------------|
|Качество ответов|Высокое. Модели GPT-4.1, Claude 4.5 показывают внушительные результаты на бенчмарках (MMLU 86-90+)|  Llama 4 и DeepSeek V3 сопоставимы |
|Скорость работы|GPT-4.1 mini, Claude Haiku оптимизированы для быстрых ответов (низкие задержки)|может быть сопоставим по скорости но только если берем GPU (на CPU задержки будут больше) |
|Cтоимость владения и использования|На старте низкие вложения, но при масштабировании расходы будут расти| Высокие затраты на старте на оборудование. В долгосроке затрат на электричество.|
|Удобство и простота развёртывания|Готовый API, не требует управления инфраструктурой| Требуется настройка серверов и сопотствующие работы, своя экспертиза в области MLOps  |

Рекомендация:
Учитывая конфиденциальность данных в качестве оптимального решения стоит рассмотреть гибридный подход:
1. Для конфиденциальных данных использовать локальные модели, развернутые внутри инфраструктуры компании. 
2. Для нечувствительных данных можно использовать облачные API, например, YandexGPT. 

Анализ моделей эмбеддингов
| Критерий  | Облачные (OpenAI Embeddings) | Локальные (Sentence-Transformers)	  | 
| --------- | ------------------------------------| ------------------------------------------------------------|
|Качество поиска|Высокое. Хорошо работают на общих данных, но могут быть менее эффективны на узкоспециализированной лексике.|Очень высокое. Специализированные модели достигают высокой точности|
|Скорость индексации|Высокая. За счет того что облачные провайдеры имеют мощную инфраструктуру.|Зависит от GPU. С использованием GPU (L4, L40S) скорость высокая. Без GPU — низкая |
|Стоимость владения|Оплата за токены. Для большого объема документов (постоянный прирост 400 страниц/мес) затраты могут быстро расти.|Нулевая стоимость. Затраты только на GPU для инференса (расчет эмбеддингов).|

Источники информации:
https://www.siliconflow.com/articles/ru/the-most-accurate-open-source-embeddings

Рекомендация:
Выбрать локальные модели эмбеддингов,  т.к. это решение лучше позволяет контролировать расходы. Качество сопоставимо с облачными.

Анализ векторных баз данных (Vector DB)
| Критерий  | ChromaDB | FAISS	  | 
| --------- | ------------------------------------| ------------------------------------------------------------|
|Скорость поиска и индексации|Средняя. Работает на CPU. Быстр на небольших объемах (до нескольких миллионов векторов), что соответствует данным QuantumForge|Высокая. Разработан Meta для поиска среди миллиардов векторов|
|Сложность внедрения и поддержки|Низкая. Простая установка через pip install chromadb и готова к работе из коробки. Имеет встроенную персистентность и удобный API|Высокая. Требует ручной реализации сохранения индекса|
|Удобство в работе|Высокое. Предоставляет простые методы, умеет интегририровать с LangChain и имеет встроенную поддержку фильтрации по метаданным |Низкое. Высокие затраты на кастомизацию. много кода для управления жизненным циклом индекса, фильтрации по метаданным плохо поддерживается|
|Стоимость владения (учёт инфраструктуры)|Низкая. Бесплатно. Простое сопровождение.|Низкая. Большие затраты на инфраструктуру. |

Рекомендация:
Выбрать ChromaDB. Данные QuantumForge (≈21,000 документов) не требуют FAISS. Ключевым моментом считаю простоту поддержи. Простое использвоание позволит быстро прототипировать и легко внедрять. Скорости хватит с учетом потребности.

Рекомендуемая конфигурация сервера
Для развертывания рекомендуемого решения потребуется сервер с GPU.

CPU: 8+ ядер 
RAM: 64-128 ГБ
GPU: NVIDIA L4 
Диск: NVMe SSD от 500 ГБ

Инфраструктурные варианты для компании:
Вариант 1 (On-Premise): Закупка собственного сервера. Плюсы: полный контроль над данными. Минусы: необходимость физического размещения и обслуживания.
Вариант 2 (Приватное облако): Аренда GPU-сервера провайдера. Плюсы: масштабируемость. Минусы: ежемесячная арендная плата.
Вариант 3 (Облачный API + Serverless): Использование облачных LLM. Плюсы: скорость развертывания. Минусы: риски для конфиденциальных данных и затраты при росте нагрузки.
